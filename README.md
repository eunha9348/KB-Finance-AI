# 전세 안전진단 & 청년 금융연계 플랫폼

전세 계약을 앞둔 2030 세대가 **이 매물이 위험한지**를 계약 전에 확인하고,
위험도에 맞는 **KB국민은행 전세자금 상품**을 바로 추천받는 서비스 프로토타입입니다.

전세사기 피해자 대부분이 20~30대이고, 대개 등기부를 떼 볼 줄 몰라서가 아니라
**떼 봐도 그 숫자가 위험한 건지 모르기 때문에** 당합니다. 근저당 3억이 적힌
등기부를 보고도 "이 정도면 괜찮은가?"를 판단할 기준이 없습니다.
그래서 판단 자체를 점수로 대신 해 주고, 그 점수에 맞는 금융상품까지 이어붙였습니다.

네이버·직방 같은 민간 플랫폼 크롤링은 쓰지 않았습니다. 공공데이터와 제휴 채널만
써야 은행 내부 시스템에 그대로 얹을 수 있기 때문입니다.

## 바로 실행

`frontend/standalone.html` 을 브라우저로 열면 끝입니다. 설치도, 서버도, 인터넷도
필요 없습니다. 데이터가 파일 안에 들어 있습니다.

지도의 원을 클릭하면 오른쪽에 진단 리포트가 뜹니다. 위험도가 어디서 나왔는지
(펀더멘털 vs 지역 컨텍스트), 근거가 된 기사가 뭔지, 어떤 상품이 왜 매칭됐는지까지
펼쳐서 보여줍니다.

## 위험도 계산

```
위험도 = 100 × ( 0.78 · f  +  0.22 · c )

f  물건 자체 (0~1)                     c  지역 환경 (0~1)
├ 선순위채권비율 (근저당+보증금)/매매가   ├ 전세가 변동성 (CV)
├ 전세가율                              └ 뉴스 감성 초과분
├ 위반건축물
├ 주거유형 (비아파트 가산)
└ 노후도
```

등급은 안전(0 ~ 29) · 주의(30 ~ 54) · 경고(55 ~ 79) · 위험(80 ~ 100).

**선순위채권비율이 핵심 축입니다.** (근저당 + 내 보증금)이 매매가를 넘으면
경매로 넘어갔을 때 보증금을 다 못 받습니다. 이게 100%를 넘는 순간이 이른바
깡통전세이고, 다른 조건이 아무리 좋아도 위험 등급으로 갑니다.

**뉴스 감성은 조절 역할만 합니다.** 처음에는 서울 평균 감성을 모든 자치구에
그대로 더했는데, 그러니까 서울 전체 위험도가 통째로 올라가면서 구별 변별력이
사라졌습니다(등급 변동 44%). 기준선을 넘는 초과분만 반영하도록 바꾸니
전세사기 보도가 실제로 몰린 관악·강서 같은 구만 차등해서 올라갑니다.

가중치가 타당한지는 직접 돌려서 확인할 수 있습니다:

```bash
python data/validate_risk.py   # → docs/risk_methodology_validation.md 재생성
```

단조성, 시나리오 4종, Spearman 상관, 감성 제거 ablation 결과가 문서로 나옵니다.
현재 기준 선순위채권비율 ρ = 0.97, 펀더멘털이 총점의 98.5%, 감성을 빼면
등급이 바뀌는 매물은 8.3% 입니다.

## 금융상품 매칭

등급 하나로 상품을 1:1 매핑하면 같은 '경고' 안에서도 조건이 전혀 다른 매물에
똑같은 상품이 붙습니다. 그래서 등급 + 선순위채권비율 + 보증금 규모를 같이 봅니다.

| 상품 | 보증기관 | 금리(참고) | 한도 | 매칭 조건 |
|---|---|---|---|---|
| 청년전용 버팀목 전세자금대출 | 주택도시기금 | 2.00~3.10% | 2억 | 안전·주의 + 보증금 ≤3억 |
| KB 청년 맞춤형 전세자금대출 | HF | COFIX 연동 변동 | 2억 | 안전·주의 + 정책한도 초과 |
| KB스타 전세자금대출 (HF) | HF | 3.70%~ | 2.22억 | 경고 + 선순위 <90% |
| KB스타 전세자금대출 (HUG) | HUG | 3.94~5.34% | 2.22억 | 경고 + 선순위 ≥90% |
| KB스타 전세자금대출 (SGI) | SGI | 3.70%~ | 최대 5억 | 보증금 >4.44억 |
| 전세보증금반환보증 안내 | HUG | — | — | 위험 |

'위험' 등급에는 대출을 매칭하지 않습니다. 보증보험 가입이 되는지부터 확인하고,
안 되면 계약을 다시 생각하라는 안내가 먼저 나가야 한다고 봤습니다.

'안전' 등급에는 **−0.3%p 우대**를 붙였습니다. 이건 KB 공시금리가 아니라 이 제안에서
새로 만드는 정책입니다. 안전한 매물을 고른 고객에게 금리로 보상하면, 은행 입장에서는
사고 확률이 낮은 대출을 늘리고 고객은 이자를 아끼는 구조가 됩니다.

> 금리·한도는 공개된 상품안내 기준 참고값입니다. 실제 조건은 신용도와 COFIX 변동에
> 따라 달라지므로, 실서비스에서는 은행 API 조회로 대체해야 합니다.

## 데이터

세 가지 모드가 있고 위에서부터 되는 걸 자동으로 씁니다.

| 모드 | 조건 | 개별 매물 |
|---|---|---|
| 실제 매물 | `data/realprice*.csv` 존재 | 실제 단지명·보증금·면적 |
| 실거래 평균 | `MOLIT_API_KEY` 또는 `SEOUL_API_KEY` | 자치구 실평균 기반 샘플 |
| 폴백 | 아무것도 없음 | 근사 평균 기반 샘플 |

### 실제 매물로 채우기 (인증키 불필요)

[국토부 실거래가 공개시스템](https://rt.molit.go.kr)에서 아파트 → 전월세 →
서울 → 최근 기간을 골라 CSV 를 받습니다. 로그인도 인증키도 필요 없습니다.
매매 CSV 도 같이 받으면 매매가 추정에 씁니다.

```bash
# 받은 파일을 data/realprice_rent.csv, data/realprice_trade.csv 로 저장
python data/etl.py
```

실제 단지명과 보증금이 그대로 들어옵니다. 다만 근저당은 등기부가 공공 API 로
열리지 않아 미확인으로 두었고, 이때 선순위채권비율은 전세가율과 같아집니다.
등기부를 연동하면 위험도가 지금보다 올라갑니다.

### API 키로 자치구 평균만 갱신

```bash
MOLIT_API_KEY=발급키 python data/etl.py     # data.go.kr, 권장
SEOUL_API_KEY=발급키 python data/etl.py     # 서울 열린데이터광장
```

매번 붙이기 번거로우면 `.env.example` 을 `.env` 로 복사해서 채워두면 됩니다.
`.env` 는 `.gitignore` 에 있어서 커밋되지 않습니다.

호출이 실패해도 서비스는 멈추지 않고 폴백 값으로 돌아갑니다. 대신 어떤 지표가
실데이터이고 어떤 게 폴백인지 UI 상단 배지에 그대로 표시됩니다. 매매만 성공하고
전세는 실패하는 경우가 흔해서 지표별로 따로 기록합니다.

## 실행

```bash
python data/etl.py               # db/housing.db 생성
python data/export_json.py       # DB → frontend/data.json
python data/build_standalone.py  # → frontend/standalone.html

python backend/app.py            # localhost:8000, Leaflet 실지도 + API
```

Python 3.9 이상이면 표준 라이브러리만으로 돌아갑니다. Flask 가 깔려 있으면
백엔드가 Flask 로 뜨고, 없으면 `http.server` 로 뜹니다.

## 구조

```
data/     risk_engine  위험도 계산
          kb_products  상품 마스터 + 매칭
          news_sentiment  2-gram 감성 분석
          etl  파이프라인 (CSV / API / 폴백)
          realprice_csv, molit_api, seoul_api  데이터 소스별 로더
          validate_risk  방법론 검증 → 문서 생성
db/       schema.sql
backend/  app.py  REST API
frontend/ standalone.html  배포용 단일 파일
          index.html  Leaflet + Chart.js 라이브 버전
```

| API | 설명 |
|---|---|
| `GET /api/properties` | 매물 + 최신 위험도 |
| `GET /api/properties/<id>` | 매물 상세 + 추천 상품 |
| `GET /api/districts` | 자치구별 평균 |
| `GET /api/stats` | 요약 통계 |

## 남은 것

- 근저당(등기부)이 제일 큰 구멍입니다. 인터넷등기소 제휴가 붙어야 선순위채권비율이
  완성되고, 그전까지는 CSV 모드 위험도가 실제보다 낮게 나옵니다.
- 위반건축물도 건축물대장 연동 전이라 시연 모드에서만 반영됩니다.
- 뉴스 코퍼스를 '전세사기' 키워드로 모아서 표본이 부정 쪽으로 치우쳐 있습니다.
  city_index 를 전체 뉴스의 부정 비율로 읽으면 안 되고, 자치구 간 상대 비교용으로만
  써야 합니다.

자세한 사용법은 [`docs/USAGE.md`](docs/USAGE.md) 를 보세요.
